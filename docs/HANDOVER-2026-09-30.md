## 1. What this project is, in two minutes

Talent Angels answers career questions using **taxonomies** — structured graphs
of occupations and skills, like O\*NET (US) and ESCO (EU). The graph is the
source of truth; the LLM is there to route questions and phrase answers, never
to invent facts.

There are four skills, and they are the product:

| Skill | Question it answers | State |
| --- | --- | --- |
| **Locate** | "Where is *nurse* in the graph?" | **Built** |
| **Connect** | "What skills does a *software developer* need?" | **Built** |
| **Pathfind** | "How do I get from *nurse* to *software developer*?" | **Empty stub** |
| **Evaluate** | "Is this route worth it, under this policy?" | **Empty stub** |

`src/talent_angels/skills/pathfind/` and `.../evaluate/` are **empty
directories** — no files at all. Half the product is unbuilt. Knowing that on
day one saves you a lot of confused searching.

The interface is deliberately dull: typed results cross every internal boundary
(`contracts/models.py`), evidence is a *pointer* to a graph node and never a
copied payload (licensing), and node IDs are suite-scoped so ESCO and O\*NET
never silently claim to be talking about the same thing. Read
[`ARCHITECTURE.md`](../ARCHITECTURE.md) before changing structure — it is short
and the rules are load-bearing.

### The two memories

The team talks about memory in two halves, and it is worth using the words:

- **Memory 1 — the driver learns you.** Your goals, your rejected routes, what
  you've already been told. Private to you.
- **Memory 2 — the city learns from all drivers.** Which routes are popular,
  where people get stuck. Aggregate, shared, the longer horizon.

**Sprint 6 built Memory 1.** Memory 2 is not started, and nothing in this
handover depends on it.

## 2. Where things stand

**Done and committed:** the "we covered this before" recall feature — the agent
now remembers what it told you in past sessions and mentions it when it's
relevant. It is measured, tested, and on by default.

**The one thing that will bite you first:** the graph does not contain the full
ESCO taxonomy. Only a tiny sample is loaded. Any question about a real
occupation will fail, and it will look like a bug in the pipeline when it is
just missing data. §5 has the fix; it takes about ten minutes.

**The big remaining build:** Pathfinder. It is the one capability that turns
"here are skills" into "here is how you get there", and it does not exist yet.

## 3. What we built this sprint (Memory 1)

### 3.1 The recall feature, in plain terms

You ask a question. Before answering, the system checks your own past
questions, and if one was about the same thing, it shows you that you already
covered it.

Three implementations were built and compared against each other on a
30-turn / 43-question test set:

| Mode | How it searches | Result |
| --- | --- | --- |
| **lexical** | keyword match (SQLite FTS5) | 2 of 36 questions had no answer; **0** false alarms |
| **vector** | meaning match (`sqlite-vec`) | 0 unanswered, but **210 false alarms** |
| **hybrid** | keyword first, meaning only if keyword found nothing | **0 unanswered, 0 false alarms** |

The 210 is the important number. Semantic search *always* returns its nearest
neighbour, so with no threshold it cheerfully answers every irrelevant question
with confident nonsense. We measured where irrelevant answers land versus real
ones and set a threshold in the gap between them (`-1.10`).

Two caveats stated honestly, because you'll inherit them:
- The threshold is calibrated from **seven** irrelevant questions. That is a
  small sample.
- All test data is **English-only**.

Recalibrate before trusting either in another language or another corpus.

### 3.2 Two decisions we reversed, and why

Both are recorded in `docs/decisions/0007-memory-architecture.md` rather than
changed quietly.

**Recall used to default to `off`, and now defaults to `hybrid`.** The original
reasoning was fair: a feature that changes what the app says back to you
shouldn't surprise anyone who didn't ask for it. The measurements ended that
question — recall scored better in every column, and shipped dormant it is a
feature nobody discovers. What makes the default safe is that `hybrid` costs
nothing on the common path (keyword search runs first; the embedding provider
is only contacted if keyword found nothing), and an install without a key or
without a built index quietly falls back to keyword-only with a single warning.

**The vector retriever used to have no relevance floor**, for the reasons above.

The invariant that protects a user who never wanted recall at all is unchanged,
and is now a test: **a question with nothing to recall leaves the system prompt
byte-identical.**

### 3.3 The rest of the sprint

- **Sessions survive a restart.** LangGraph checkpoints go to SQLite.
- **Forgetting actually forgets.** Three scopes — this session / this person /
  everything — and the tests read the **raw bytes off disk** to prove forgotten
  text is gone, not just missing from the table. This exists because a search
  index that outlives a reset while the app says "Forgotten" is worse than no
  reset at all.
- **A graph cache** so repeat lookups don't re-hit Neo4j, with a test that
  proves it fires in the real code path (not just in isolation, which is how
  caches quietly stop working).
- **A golden eval set** for deciding between near-tied search results — the
  judgement users actually notice, which recall metrics can't measure.

## 4. Running it

```bash
# 1. A graph database (once) — the compose file lives in the TAXONOMIES repo
cd ../TA-taxonomies && docker compose up -d && cd -
#    ...or, for the full ESCO graph, follow docs/esco-full-load.md (see §5)

# 2. Install this repo
uv sync
uv run ta-agent            # the chat UI
uv run ta-mcp              # the programmatic edge

# 3. Ask something
uv run python -m talent_angels.cli query "What skills does a nurse need?"
uv run python -m talent_angels.cli connect --suite onet "What skills does a software developer need?"

# 4. The tests
uv run pytest -q --ignore=tests/integration   # 653 pass, no database needed
uv run ruff check . && uv run mypy src        # both gate CI
```

`TA_RECALL` picks the recall backend: `hybrid` (default), `lexical`, `vector`,
or `off`. If you want to see why the vector path needs a threshold, run
`uv run python -m talent_angels.evals.recall --vector` and compare.

## 5. ⚠️ The first trap: the graph is nearly empty

If you do one thing from this document, do this one. You will otherwise lose
an afternoon to what looks like a broken pipeline.

**Verified live on 2026-09-30:**

| Taxonomy | Actual state |
| --- | --- |
| **O\*NET** | Loaded and healthy — 31,942 nodes, 1,022 occupations, 19,130 tasks |
| **ESCO** | **Not loaded.** Only a 6-occupation / 51-skill *sample* is present. The real labels don't exist at all |

So: O\*NET questions work, ESCO questions about any real occupation fail.

**This is not a broken pipeline and not missing data — it's a known, documented,
previously-measured load that nobody has re-run.** `docs/esco-full-load.md` has
the full procedure: ~22 seconds to ingest, 45 MB on disk, and the source files
are already downloaded in the `TA-taxonomies` repo. The only reason it hasn't
run is that it targets a dedicated database container which was removed from
this machine.

Two ways this bites people, both documented in that file:

- `python -m ta_taxonomies.suites.esco.load` **defaults to a sample mode that
  wipes the ESCO labels first.** Always pass `--mode` explicitly and check
  which database you're pointing at.
- The load is supposed to go in its **own** container on port 7690, so it never
  touches the day-to-day database on 7687. Don't "helpfully" point it at 7687.

**Validate after loading:** you should see thousands of nodes. Sixty-one means
you loaded the sample again.

**Related and equally dormant:** the Tier 5 semantic search in the graph layer
is fully written, committed, and has **never been run** — there is no vector
index in the database at all. It's a one-command batch job against an
already-loaded graph, and it would improve search for the product people use
today, with no pilot involved.

## 6. What's left — your backlog

Ordered by what I'd do first. Effort estimates are honest ones, not guesses.

### 6.1 Pathfinder — the big one

**State:** empty directory. Asking "how do I get from nurse to software
developer?" gets a correct, honest "not implemented yet" message. The
fall-through bug that let it return a plain skills list instead is **already
fixed** (`assistant/agent_loop.py`) — don't re-do that.

**Before you write code, decide:** what *is* a path? What's a step? What does
it cite? And what is a **disqualifier** — a gap too wide to bridge is a finding,
not an error.

**The design constraint that matters:** route finding is deterministic work. It
belongs in a tool with explicit depth limits, not in a model prompt. The
architecture rules push determinism down into code on purpose.

**The case to design against:** the negative result. "You cannot get from nurse
to software developer in one hop, and here's the actual gap" is genuinely useful
and expensive to fake. Inventing a plausible-sounding route is the failure
mode, and it's the one the model will drift toward if you let it.

Rough size: a few days, if the contract question above gets answered first.

### 6.2 Evaluate — also an empty stub

Same situation, and worth deciding **with** Pathfinder rather than after it.
Scoring a route needs a route to score. The team has a "named policy" idea
recorded in the old handoff — start there, and check whether it needs a
`contracts/` change (that path needs a mentor's review).

### 6.3 The other taxonomies — 2 of 5 sources exist

Agreed back in ADR-0006, still not built. In value order:

| Source | Effort | Notes |
| --- | --- | --- |
| **BLS / SOC** | Medium | **Do this first.** SOC is the spine that ties O\*NET, BLS and ESCO's ISCO mapping together. A crosswalk with no spine is four disconnected graphs. Also brings US employment projections |
| **SFIA** | Medium | **Structure only** — codes, names, level numbers. **Never** its descriptive text; that's a licensing constraint, not an oversight. Levels are first-class: level 4 of a skill is not level 7 of the same skill |
| **Sweden JobTech** | Large | CC0-licensed, ~6.9M live job postings. Lowest priority — additive signal, not part of the crosswalk backbone |

Before building JobTech, resolve a question ADR-0006 left open: does its
taxonomy actually carry ESCO concept mappings? Nobody has checked. Don't
assume.

### 6.4 Quality bugs still open

- **Two suites disagreeing on the same question.** The connect step re-uses the
  user's original wording instead of the node it just resolved to, so ESCO and
  O\*NET can answer differently. Multi-suite answers also show as two separate
  blocks rather than one combined answer. *This is the most user-visible thing
  left — I'd fix it first.*
- The tool loop sometimes fetches extra data on a simple "what does X do".
- O\*NET's tool-related skills don't show as essential/optional like the rest.
- Asking the agent something personal ("what do you know about me?") gets
  treated as a failed lookup instead of answered from memory.
- Minor: a stated goal doesn't always reach the profile; occasional blank labels
  on saved answers; memory is used when *writing* the answer but not while
  *reasoning*; the 5-item preview cap on skill lists has no "show more".

## 7. Traps and rules that will save you

**Project rules** (breaking these blocks CI or review):

- Python 3.11+, package `talent_angels`, src layout. **ruff** for lint and
  format, **mypy** for types — mypy blocks CI. **pytest**, offline by default;
  anything needing a live database lives in `tests/integration/` and must skip
  with a reason.
- Every commit is **DCO-signed**: `git commit -s`. PRs target **`dev`**, never
  `main`.
- Some paths need a mentor's review before merge: `src/talent_angels/contracts/`,
  `tests/evals/`, `ARCHITECTURE.md`, `CLAUDE.md`, `AGENTS.md`, `.github/`.
- **Never commit `.env` or secrets.** The local `.env` is gitignored and holds
  a working API key; embeddings need no new key.
- **Don't delete the 656 historical query-detail files** without asking. They're
  user-content history, not clutter.

**Design rules** (from `ARCHITECTURE.md`, and the ones people break by accident):

- **Only the main assistant talks to the user.** Skills don't own the goal.
- **Typed results cross every boundary** — never prose between components.
- **Only graph data is cited as taxonomy fact.** If the model inferred it, say
  so. This is the honesty rule and it is not negotiable.
- **Evidence is a pointer, not a payload.** Don't copy taxonomy text into your
  own structures; link the node. This is what keeps licensing clean.
- **Determinism goes in code**, not prompts — traversal, depth caps, top-K cuts
  and scoring.
- **`group_and_sort_locate()` is mandatory after every `locate()`.** Confidence
  is a declared method label, **not** a probability — don't present it as one.
- **Skills run inline by default.** Only reach for a subagent when you have a
  measurement showing isolation pays.

**Don't add a second database.** The vector index is a table inside the existing
`memory.db` specifically so that forgetting stays one `DROP TABLE` and one
erasure path. Adding a separate store would re-create the exact class of bug we
already fixed once.

## 9. If you're a different model picking this up

The facts most likely to cause a wrong decision if you don't have them:

- Package `talent_angels`, Python 3.11+, `uv` for everything, ruff + mypy
  (mypy gates CI), pytest offline by default.
- The graph is the fact source; the LLM routes and phrases. Never the reverse.
- The recall default is `hybrid` **on purpose**, and the reasoning is in
  ADR-0007. Don't "fix" it back to `off`.
- The vector floor (`-1.10`) is calibrated from a **small** sample on
  **English-only** data. If you change it, re-measure and say so.
- ESCO is a sample, not the real taxonomy (§5). Any conclusion drawn about ESCO
  quality right now is provisional.
- The user is still learning this system and asks for plain-English narration
  before technical detail. Explain *why*, and quote measurements rather than
  adjectives.
